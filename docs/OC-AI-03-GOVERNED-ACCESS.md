# OC-AI-03 — Dynamic governed research access (experimental)

`createGovernedResearchTools(archive,{candidateDocumentIds,authorize,audit})` creates an in-process, read-only research facade. An authoritative host supplies a bounded set of candidate document IDs, a synchronous policy callback, and a synchronous audit callback. Authorization is re-evaluated on each access; denied search candidates are skipped without reading their content. An authorization exception denies access; an audit exception aborts the operation before protected content is read. No decisions are cached.

**This is not a standalone security boundary.** The host must authenticate identity, bind the authorization and audit callbacks to trusted context, control the archive instance, and ensure a durable audit sink. The legacy unscoped and statically scoped facades remain available to trusted code. Audit callback success does not prove durable storage. Candidate IDs are supplied by the host and cannot exceed 100; search is a literal case-sensitive scan, not complete FTS. Mid-call policy changes cannot retroactively revoke already returned data. Network/API endpoints, multi-tenant partitioning, policy versioning, audit persistence, concurrency guarantees and independent security review remain future gates.
